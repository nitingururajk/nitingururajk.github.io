TokenFlow Lab: Visualizing LLM Streaming Speed

Apr 30, 2026 4 min read

TokenFlow Lab is a small simulator for seeing what different LLM streaming speeds feel like. Paste some text, pick a tokenizer, set a tokens-per-second value, and watch the response appear in a chat-style output bubble.

Short version: TokenFlow Lab is not an inference benchmark. It is a visual tool for building intuition around output token rate, token boundaries, and perceived streaming speed.

What it shows

Tokens per second is easy to quote and hard to feel. A model that produces 20 tokens per second, 60 tokens per second, or 150 tokens per second can look very different in a real chat interface. TokenFlow Lab makes that visible without needing to run a model.

The app streams your selected text token by token, tracks generated tokens, shows elapsed time, and lets the TPS slider update the stream while it is running. You can pause, reset, switch tokenizer profiles, and compare steady output against more variable chunk timing.

Decode speed, not prefill speed

The TPS control represents decode speed: how quickly output tokens appear after generation has started. That is the part users experience as the response "streaming" onto the screen.

It does not model prefill or prefix processing. In real inference, the system still has to process the prompt before the first output token appears. That first-token delay can depend on prompt length, cached prefixes, batching, hardware, queueing, network latency, and serving stack behavior. TokenFlow Lab focuses on the output phase so the visual effect of decode TPS is easier to isolate.

Tokenizer profiles

A token is not necessarily a word. The same text can produce different token counts depending on the tokenizer used by the model. TokenFlow Lab includes GPT-style tokenizer profiles such as cl100k_base and o200k_base, plus simpler word and character modes for comparison.

There is also an upload option for a compatible tokenizer.json, which is useful when you want the preview to match a specific model family or fine-tuned model more closely. The token count and the generated-token counter are always tied to the selected tokenizer profile.

Streaming modes

The simulator has two output styles. Steady TPS shows a clean, even-paced decode stream at the selected rate. Realistic mode adds jitter and small bursts so the output feels closer to how streaming often arrives in a UI.

Both modes still respect the selected TPS target. The difference is cadence: steady mode is useful when you want a clean speed comparison, while realistic mode is better for judging how uneven chunk timing changes the perceived smoothness of a response.

How to read it

Start with sample text, choose a tokenizer, and move the TPS slider. Low values make individual tokens obvious. Mid-range values feel like a typical streamed chat response. High values start to feel less like typing and more like a fast reveal.

The useful question is not only "how many tokens per second is this?" It is "what does this speed feel like to a person reading the response?" TokenFlow Lab is meant to make that question easier to answer visually.

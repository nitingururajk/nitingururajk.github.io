TokenFlow Lab: an LLM streaming simulator

Paste some text, set a token rate, and see how quickly you can read along.

N By Nitin April 30, 2026 3 min read

I built TokenFlow Lab to see what different token rates look like in a chat window. You give it text and a speed, and it streams the text in your browser. You can try 20, 60, or 150 tokens per second without running a model.

Before you start: This is a simulation. It plays back text you've already supplied, so it won't measure a model's performance.

What it shows

The app shows the text token by token, with a running token count and elapsed time. The TPS slider works while the stream is running, so you can change the speed without starting over. There are pause and reset controls, a choice of tokenizers, and two streaming modes.

What the speed setting measures

The TPS control represents decode speed: how quickly output tokens appear once generation has started.

A real model also has to process the prompt before it can return the first token. That delay depends on prompt length, cached prefixes, batching, hardware, queueing, the network, and the serving software. TokenFlow Lab skips this prefill step; the speed setting applies only to the output.

Tokenizer profiles

A token can be a word, part of a word, or a character, depending on the tokenizer and the text. The app includes GPT-style profiles such as cl100k_base and o200k_base, along with word and character modes for comparison. Changing the tokenizer can change the token count for the same text.

You can also upload a compatible tokenizer.json if you want to use the tokenizer from a particular model family or fine-tuned model. Both the total and the running token count use whichever profile you've selected.

Streaming modes

Steady TPS releases tokens at an even pace. Realistic mode adds jitter and small bursts, closer to the uneven delivery you sometimes see in a chat app.

Both aim for the same selected TPS. Switch between them at one speed to see how much the pauses and bursts affect reading.

Try it

Open the demo, pick some sample text and a tokenizer, then start the stream. Turn the slider down until you can follow each token. Bring it back up while reading the same passage. At higher speeds, you'll probably see the text arrive faster than you can read it.

Keep the tokenizer the same when comparing speeds. Otherwise, a change in token boundaries can affect how much text appears each second, even at the same TPS.
